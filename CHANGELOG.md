# Changelog

## Unreleased

- Security (fail closed, 0.4.2 TS differential): `IntentV2Context.fromJSON` returned nil (no context) for a PRESENT v2 context that is not a JSON object (JSON null included), so a misconfigured verifier silently ran without Intent Layer v2 enforcement where the reference refuses. It now returns a malformed context (every v2 check that would be reported fails with `malformed v2 context: the v2 verifier context must be an object`); `fromJSONText` keeps refusing non-object text.
- Fix (0.4.2 TS differential): the action handed to the layer ceilings, schema conformance, canonical projection and accumulators uses `String(p.action?.verb)` / `String(p.action?.resource)` like the reference (absent => "undefined"); a PCActn without `action.resource` no longer fails `layers` where TS passes. New `IntentV2DiffTests` runs the shared `k042-intentv2-cases` oracle: every decision agrees (118 reason texts still worded differently, counted).

- Security / Breaking (0.4.2, R3-01): a pure post-quantum or hybrid Intent Layer v2 session root verifies only under the VERIFIER's pin for its signer, the new verifier-context member `session.pq_pins` (`{<ed25519 key>: <pq_pk>}`), never under the root's own `principals[].pq_pk`. No pin fails closed (`session root suite '<alg>' needs the signer's PQ key pinned by the verifier (pq_pins) ...`), a pin that differs from the root's `pq_pk` fails, and a signer principals entry that declares another key fails. A malformed `pq_pins` (not an object of strings) is a malformed session context. Ed25519 roots are unchanged. Conformance `session-root-*-unpinned`, `-pin-mismatch`, `-pin-other-signer`, `-principal-entry-mismatch`, `ctx-session-pq-pins-*`. `IntentSession.verifyRoot(s, pqPins:)`.
- Fix (fail closed, standalone chain API): `Capability.verifyChain` given BOTH the verifier's stored grant (trusted root) and a PQ pin for the root issuer authorised the root on the stored grant and ignored a pin that names a different key. Both must now agree: a disagreeing pin refuses with `hop 0: root suite '<alg>': the server-side PQ pin for the root issuer (policy.pqPins) does not match the stored grant's pq_pk (fail closed)`, as in the TypeScript reference. The PCActn verify path passes only the stored grant and is unchanged. New shared vectors `chainpin-pure-pq-root-trusted-root-and-matching-pin`, `chainpin-pure-pq-root-trusted-root-wrong-pin`, `chainpin-hybrid-root-trusted-root-wrong-pin`.
- Rule 15: the tracked `acc.keyset_versions[root]` is exactly `{version, digest}` (digest = base64url(sha256(strictCanonical({"d":"atlas-pca/sequencer-keys-ref/v1","k":set})))); a presented key set below the tracked version (rollback) or at it with another digest (equivocation) is skipped; a malformed tracked entry fails `accumulators`. Rule 13: the revocation evidence (and the tracked last epoch) is closed to `{epoch, revoked}`; the `intent_revocation` primitive treats every input member other than its parameters as evidence.
- Intent Layer v2 rule 19 and the W-A security batch. Committed map (V15): `intent_session.map_form` ("commit" only) with the `pca-intent:v2c:` goal; context `map.disclosure`, policy `map` (`require`, `max_residual_risk_ppm`); a new `map` check after `accumulators` (salted kind-tagged leaves, RFC 9162 openings, closed and typed leaves, the exact cell of the action, ε), reported when the PCActn commits or the policy requires it; `PCA.intentMapCommitPrimitive` / `intentMapPrimitive`. Rule 15: a receipt lives at most 15 min and must be at most `acc.max_receipt_age_s` (default 900) old; key sets carry a required `version` (>= the tracked `acc.keyset_versions[root]`) and must be at most `acc.max_keyset_age_s` (default 3600) old and at most 60 s in the future; a key entry's `not_after` must be >= now - 60 s (a retired key stops verifying). Rule 13 step 7: the session root names a dedicated revocation authority (`revocation.key`, required, never a principal); the evidence is exactly `{epoch, revoked}` with the full sorted revoked list (its revset root is the signed root, epoch == set_size), checked append-only against the tracked `session.revocation_last` (no rollback, no drop, no equivocation); the non-membership proofs are gone; `intentRevocationPrimitive` takes `{epoch, revoked, session, authority, ids, now, max_age_ms, last?}`. The v2 policy is closed to `{session, schema, acc, map}`. The runners execute `intent_map_commit` / `intent_map`.
- Suite capability (packages/pca/conformance/SUITES.md): the ONE suite dispatch (`PQ.resolve` / `PQ.verifySuite`: leaf, capability hops, threshold shares, pq artifacts, Intent v2 artifacts) now verifies every registered suite CryptoKit provides (macOS / iOS 26+, pure mode, empty context): `ml-dsa-65`, `ml-dsa-87` (`MLDSA65` / `MLDSA87`), `hybrid-ed25519-ml-dsa-65` / `-87` and the SUF-CMA `hybrid-nested-ed25519-ml-dsa-65`, with per-suite lengths. CryptoKit has no SLH-DSA, FN-DSA or LESS and the package takes no third-party crypto, so `slh-dsa-*`, `fn-dsa-*`, the LESS pair and their hybrids (and the ML-DSA suites on an older OS, where they used to fail as a bad signature) fail closed with the distinct reason `unsupported_suite: <alg>`; an unregistered alg keeps `unknown signature alg`. New public manifest `PCASuites.registered`, `PCASuites.supported` (runtime), `PCASuites.unsupportedSuiteReason`. `ConformanceTests` takes the manifest and asserts `unsupported_suite` instead of skipping.
- Intent Layer v2 (additive; conformance rules 13-18 and the v2 pipeline): `intent_session` is a new OPTIONAL SIGNED top-level PCActn field (closed wire: `session`, `root`, `schema`, `seq` in [0, 2^31-1], `acc` <= 16 claims, `facts` <= 16, `classes` <= 8, `labels` <= 16 distinct digests, `offer_set`, `prov` <= 32 paths of 1..8 refs); with it the `intent` goal is `pca-intent:v2:<session>:<map_digest>`. New `public struct IntentV2Context` (verifier state + policy, `fromJSON` / `fromJSONText`); every `PCA.verify` overload gains a defaulted `intentV2: IntentV2Context? = nil`. After `intent` the verifier reports, each only under its condition, `schema` (signed action schema, closed-world conformance), `intent_session` (session root, principal-signed delta chain, revocation epoch with sorted-Merkle non-membership and the stricter Δ_rev), `layers` (G^org / G^site / G^std through the predicate DSL with the linear-time regex subset and per-document budget), `accumulators` (site-local pre-state or sequencer receipts resolved through the root-signed `pca-sequencer-keys` set; monitors), then the W-B unit `facts` / `provenance` / `classes` (oracle facts, relational dimensions, offer sets; per-parameter provenance with label receipts and flow rules; classifier quorum). Without the member and without an active v2 policy the verdict is unchanged. Strict values (README "strict values, absent vs null, suite capability"): every numeric field a safe integer, every list a JSON array, own-member lookups; an ABSENT optional member means empty / default and a member present with JSON null (or of the wrong type) is malformed; a malformed top-level context member (`policy` and its members, `params`, `schema`, `session`, `acc`, `layers`, `wb`) fails `schema`, `intent_session` and (with the member) `accumulators`; a clock that is not a safe integer fails every v2 check; `__proto__` / `constructor` / `prototype` are refused as accumulator, monitor and parameter names; S `layers.org` / `layers.std` null is malformed and `revocation.pq_pk` pins a PQ revocation key; revocation epochs and non-membership proofs are strictly typed; held grants must be capability objects with an implemented suite. The W-B artifacts (`pca-fact`, `pca-offer-set`, `pca-labels`, `pca-intent-classification`) may carry `alg` / `pq_pk` / `pq_sig` (`alg` and `pq_pk` signed): a non-string `alg` is malformed, an unimplemented suite is refused with `unsupported_suite` before anything else about the artifact, an ed25519 artifact carries no PQ members, and a PQ or hybrid signature verifies only under the trusted-side pin (oracle / site / label key `pq_pk`, classifier `pq_keys`). The v2 policy (`{session?: {require?, max_revocation_age_s?}, schema?: {closed_world?}}`) and the W-B / layers policies are closed and typed (a null or non-boolean flag, a bad age or an unknown member is malformed; a layer is exactly `{predicates}`); provenance class lists sort in UTF-8 byte order; new `PCA.intentReadPurposePrimitive` (`primitives.intent_read_purpose`). Every v2 signature goes through the suite dispatch; an alg it does not resolve fails closed with `unsupported_suite`. `PCA.intentV2Env` returns the verifier-computed predicate env (`canon`, `acc`, `mon`, `world`, `prov`, `class`). The rule-10 caveat evaluator treats a well-formed `intent_session` caveat as satisfied. Rule primitives: `PCA.intentSchemaPrimitive`, `intentRevocationPrimitive`, `intentWorldPrimitive`, `intentProvenancePrimitive`, `intentClassifierPrimitive`, `intentWBActivePrimitive`; `ConformanceTests` passes `context.intent_v2` on every vector, runs those primitive tables (skipping a table the corpus does not carry yet, and a `requires_suite` the dispatch lacks), and `IntentV2KillTests` / `IntentWBKillTests` pin every boundary and the check order. There is no Swift diff-fuzz driver (the Swift gate is `ConformanceTests` + the counterexamples loop). Compiled (`swift build --build-tests`); tests not run here (code freeze).
- Intent Layer M2 (additive): `intent` is a new OPTIONAL SIGNED top-level PCActn field (`{ref, map_digest, goal_salt, fidelity_ppm, residual_risk_ppm}`, closed member set; a malformed slot fails `wire`). New `public struct IntentPolicy` (`require`, `minFidelityPpm: Double?`, `maxResidualRiskPpm: Double?`, `isActive`, lenient `fromJSON(_:)`) and `PCA.intentGoalCommit(ref:mapDigest:goalSalt:)`; every `PCA.verify` overload gains a defaulted `intentPolicy: IntentPolicy? = nil` parameter (existing call sites unchanged). The `intent` check runs after `counter` and is reported iff the PCActn carries `intent` or the policy is active (it binds the slot to the root grant's first `envelope` caveat `goal_commit`, then applies the fidelity floor / residual-risk ceiling; a misconfigured threshold fails closed). Without the slot and without a policy the verdict is unchanged. The conformance runner passes `context.intent_policy` through.
- Intent policy thresholds are judged by NUMERIC VALUE whatever the lexical form (`950000.0`, `1e6` valid; `-0`, `-0.0`, fractions, negatives, > 2^53-1, null/bool/string misconfigured). New `IntentPolicy.fromJSONText(_:)`; the conformance runner accepts `intent_policy_json` (raw text, wins over `intent_policy`). The lenient JSON loader now keeps the sign of an integer-form `-0` (`.double(-0.0)`, as `JSON.parse`), where it used to read `.int(0)`.

## 0.4.1 - 2026-10-12

- Security (policy layer): caveats on the root grant outside the envelope are now evaluated like delegated caveats; new policy_caveats/evaluate_caveats helpers (incl. max_spend). The core verifier still does not evaluate caveats. Swift API: `PCA.policyCaveats(grant:chain:)` and `PCA.evaluateCaveats(_:context:)` (returns `(ok: Bool, failed: [String])`; total, fail-closed on unknown types; `max_spend`, `expires`, `not_before`, `rate`, `max_blast_radius`, `reversibility_max`, `delegation_depth`, `budget_alloc`). `PCA.verify` still does not evaluate caveats. Corpus: `primitives.caveat_eval` (41) in `R041CaveatConformanceTests`.
- Threshold share signatures are validated per suite at the wire stage (was a fixed 64 bytes): absent `alg` = ed25519 (64-byte `sig`, no `pq_sig`), `ml-dsa-65` (3309-byte `sig`, no `pq_sig`), `hybrid-ed25519-ml-dsa-65` (64-byte `sig` + required 3309-byte `pq_sig`); a non-string / null / unknown `alg` is a wire failure; a share's `pq_pk` is not judged by the wire (`Threshold.verifyShare` owns it). A pure ML-DSA-65 share can now be carried. Corpus: 20 `r041-share-*` vectors; `ConformanceTests` skips a vector whose `requires` names a suite Swift does not implement (`ml-dsa-87`, `slh-dsa-sha2-128f`).
- PCA-Action header: not applicable (this package has no HTTP middleware).
- Version: Package.swift carries no version (SwiftPM uses the git tag); this entry is 0.4.1. Built and tested on Linux (Swift 6.0.3, swift-crypto + liboqs via `tools/pca-audit/swift-mutate/linux-prep.sh`).

## Unreleased (BREAKING)

- Parity (depth caps): a capability hop's body digest is now computed over the STRICT canonical form, like the reference (`hashCanonical` in hash.ts is strict). A hop body nested deeper than 32 levels (or otherwise outside the strict profile) is refused with `hop N: malformed body`; it was hashed leniently before (shared vector `depth-chain-34`). The non-strict paths (lenient canonicalization of a caller-supplied grant / Merkle leaf, the corpus loader `parseLenient`) are bounded at `Canonical.MAX_LENIENT_DEPTH` = 1024 instead of recursing without limit, and lenient canonicalization of an out-of-profile value now yields "" instead of a truncated prefix. The unused recursive `JSONValue.from(foundation:)` is removed. Shared `primitives.depth` vectors (31 / 32 / 33 / 100000 levels on every entry point) run in `ConformanceTests.testDepthVectors`.
- Linux: the package now builds and passes its tests on Linux (Swift 6.0.3) with real ML-DSA-65, via `tools/pca-audit/swift-mutate/linux-prep.sh` (swift-crypto for CryptoKit, liboqs for ML-DSA-65, on a patched copy). The round-6 changes below were compiled and run there for the first time: every ML-DSA-65 / hybrid vector runs and passes.

- R6-03/R6-04 (parity): `Threshold.verifyShare` validates the WHOLE signer set like the reference (unknown / wrong-case roles, malformed keys, empty / null / short `pq_pk` anywhere, one key per role, one role per key, a duplicate (role, key) only with the same `pq_pk`); `t` must be 1, 2 or 3 (0..255 was accepted); `share.role` is required; new `signerSetHashJSON` hashes raw entries in UTF-8 byte order. R6-05: `Capability.verifyChain` applies the reference per-hop type check (`wellTyped`). Round-6 shared vectors run in `ConformanceTests` (`testR6ThresholdSet`, `testR6SignerSetHash`, `testR6Malformed`). NOT compiled or run: no Swift toolchain exists on the cloud farm and the Mac does not run builds; parity is by code reading against the Python/.NET implementations that pass the same vectors.
- R6-02 (security): a signer-set role that registers a `pq_pk` now REQUIRES a PQ (pure or hybrid) threshold share; an ed25519-only share for that role is refused, so an Ed25519 break no longer forges a hybrid-registered role (parity with the TypeScript reference). Corpus: `agent-bound-signerset-with-pq-pk` is now `valid:false`; new positive `agent-hybrid-signerset-with-pq-pk`.
- R5-A1 (security): threshold-share verification is now signer-set PINNED, no longer self-vouched. The share must be for the one key the signer set registers for its role, a PQ/hybrid share verifies only under the set's registered `pq_pk` (a differing share `pq_pk` is refused), the share-suite tag is part of the signed bytes (a classical share cannot be relabelled hybrid), and the signer-set hash now includes a registered `pq_pk` (parity with the TypeScript reference). New corpus vectors: `agent-not-in-signer-set`, `agent-bound-signerset-with-pq-pk`, `agent-hybrid-relabel-*`.

- Suite policy defaults documented: no list = no restriction, an empty list refuses everything, and the hosted API defaults to ed25519 + Ed25519 hybrids (README lists the exact list to pass offline).

- R4-01: `Capability.verifyChain` now takes the root's PQ authority from the verifier, exactly like the TypeScript reference (R3-01). Two new trailing parameters, `pqPins: [String: String]?` (root issuer Ed25519 b64u -> PQ public key) and `trustedRoot: JSONValue?` (the verifier's own stored root capability). A non-ed25519 (pure `ml-dsa-65` or hybrid) ROOT hop is accepted only if `pqPins[root.issuer]` equals the root's `pq_pk`, or `trustedRoot` is the root itself (same content hash). Otherwise it is refused with `hop 0: root suite '<alg>' needs a PQ key pinned for the root issuer (policy.pqPins) or the verifier's stored grant (policy.trustedRoot); the root's own pq_pk proves nothing about who issued it (R3-01)`. Before, a pure-PQ root signed with the attacker's own ML-DSA key but naming a victim Ed25519 issuer verified. Callers of `verifyChain` on a root they did not load from their own store must now pass `pqPins`. `PCA.verify` is unchanged in behaviour (it passes its grant as `trustedRoot`). Internally `PQ.resolvePqKey` is the single choke point: `PinnedPQ` has a `fileprivate` initialiser and is the only key type `PQ.verifySuite` accepts, so the PQ verify cannot be called with an artifact key. `PQ.verifyLeaf` remains as an explicitly caller-vouched entry for threshold shares and `pq_artifact` signatures.
